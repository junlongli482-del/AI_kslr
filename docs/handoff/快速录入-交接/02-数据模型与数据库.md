# 02 · 数据模型与数据库

## 1. 数据库

- 开发：容器 `jinban-dev-postgres`，库 `quickentry`，schema `jinban`，端口 55436。
- 生产：compose 内独立 postgres，库 `quickentry_prod`，卷 `pgdata`。
- 迁移：Flyway，`apps/api/src/main/resources/db/migration/`。
  - `V1__quick_entry.sql`：任务、文件、题目版本、试卷版本、模板、事件。
  - `V2026102401__folder_tree.sql`：文件夹 + `qe_task.folder_id`。

## 2. 表结构（当前）

### qe_task（任务，审核草稿存这里）

```sql
id                varchar(64) pk
title             text
mode              varchar(24)  -- textbook | questions | paper
generate_answers  boolean
channel_policy    varchar(24)  -- low_first 等
status            varchar(24)  -- uploaded/queued/running/ready/failed/interrupted/committed
stage             text         -- 中文阶段名，展示用
message           text
review            jsonb        -- 审核结果（完整 result，见第 5 节）
revision          integer      -- 草稿版本，保存时乐观锁
committed_revision integer
created_at / updated_at
folder_id         varchar(64) → qe_folder(id)   -- 2026-10 新增
```

### qe_file（上传文件）

```sql
id, task_id, name, role(question|answer|mixed), storage_key, sha256, size, sort_order, created_at
```

`storage_key` 形如 `tasks/{taskId}/{docId}/origin/xxx.pdf`，通过 `/api/assets?key=` 读取。

### question_revision（题目版本，入库时写入）

```sql
id, logical_id, task_id, review_revision, source_question_id,
number, stem, content jsonb, content_hash, status, created_at
```

- `logical_id` 跨版本稳定；`content` 是完整题目 JSON；
- `content_hash` 用于去重与变更检测；
- 唯一键 `(task_id, review_revision, source_question_id)`。

### paper_revision（试卷版本）

```sql
id, task_id, review_revision, title, mode, content jsonb, created_at
```

### paper_question（试卷-题目关联）

```sql
paper_id, question_id, sort_order, score
```

### source_template（原卷模板）

```sql
id, paper_id, content jsonb, review_status, scan_capability
```

`content` 含 `{template:{blanks,annotations,student_zones,bracket_status}, question_regions, documents}`。
`blanks` 是括号归属的唯一来源，导出时补 `blank_label`。

### qe_stage_event（阶段流水，排障用）

```sql
id bigserial, task_id, stage, status, message, created_at
```

### qe_folder（文件夹，无限层级）

```sql
id varchar(64) pk, parent_id → qe_folder(id), name, sort_order, created_at
```

规则：只能删空目录（无子目录、无任务）。

## 3. 任务状态机

```
uploaded ──start──> queued ──> running ──> ready ──commit──> committed
                                   │
                                   ├──> failed（可 retry）
                                   └──> interrupted（AI 无响应，可 retry）
```

- `ready` 之后审核页可编辑，草稿存 `qe_task.review`，`revision` 每次保存 +1；
- `commit` 需要 `revision` 匹配，成功后写题库/试卷库并置 `committed`；
- `committed` 的任务不能删除。

重试（`/retry`）复用已完成阶段缓存；MinerU 结果、LLM 调用结果都在 `data/tasks/{id}/` 下缓存。

## 4. 磁盘 data 目录

```
data/
  tasks/{taskId}/
    state.json                 任务状态（AI 侧）
    result.json                最新结构化结果（审核初稿）
    files.json                 上传文件索引
    llm/                       每次 LLM 调用缓存：{name}-{hash}.json（含请求、响应、usage）
    mineru/                    MinerU 原始 zip / content_list
    raw/                       页图、裁图（assets 服务根目录）
  uploads/                     原始上传
  settings/
    prompts.json               提示词覆盖（含 history）
    concurrency.json           并发设置
```

`QUICK_ENTRY_DATA_DIR` 可改根目录；生产挂载 `/data` 卷。

约定：

- 坐标 `bbox` 为相对页面的 0–1 归一化，顺序 `[x0,y0,x1,y1]`；

- 填空令牌写在文本里（`{{blank}}`），答案在 `blanks[].answer`；
- 标签是 AI 产出、人工可改；`tag_status` 为 `ok` / `tag_failed` / `manual`。

## 6. 常见查询

```sql
-- 某任务题目
SELECT number, stem, content->'attributes' FROM jinban.question_revision WHERE task_id='...';
-- 未提交任务
SELECT id,title,status,stage FROM jinban.qe_task WHERE status <> 'committed' ORDER BY created_at DESC;
-- 某目录（含子目录）任务
WITH RECURSIVE sub AS (
  SELECT id FROM jinban.qe_folder WHERE id='F'
  UNION ALL SELECT f.id FROM jinban.qe_folder f JOIN sub s ON f.parent_id=s.id
) SELECT t.* FROM jinban.qe_task t WHERE t.folder_id IN (SELECT id FROM sub);
```
