## 3. 结构性技术债

1. `App.vue` 超过 700 行，建议拆 review / tasks / settings 三个页面组件；
2. Java 端缺少单元测试，`TaskService` 状态机复杂，改动风险高；
3. `core.py` 单文件过大，建议拆 structure / answer / tagging / geometry；
4. 导出 schema 只有 `p1-export-v1`，没有版本化变更记录；
5. 前端知识点树是构建时打包，树更新要重新发版（可改为接口下发）；
6. 任务清理没有定时策略，`data/tasks` 会持续增长。

## 4. 下一阶段建议路线

1. **稳定识别**：真实卷 20 份回归，统计题框/题组/答案匹配错误率；
2. **打标评测**：金标 100 题，按验收线打分，不达标先调前缀；
3. **审核提效**：括号批量归属、问题题一键过滤、键盘快捷键；
4. **下游对接**：导出样例 + 增量接口（`updated_at`）；
5. **运维**：备份脚本、日志轮转、成本面板。

## 5. 不要做的事

- 不要把批阅逻辑写进本仓库；
- 不要用正则“猜”语义（填空、答案匹配都交给 AI）；
- 不要在题目上存教材版本/章节（多版本，存了就是错的）；
- 不要改提示词常量来调效果（用设置页）；
- 不要 force-reinstall 依赖（Pillow/pdfium 事故）。
