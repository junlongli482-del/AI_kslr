### 启动 / 更新

```bat
docker compose --env-file deploy\prod\.env.prod -f deploy\prod\docker-compose.yml up -d --build
docker compose --env-file deploy\prod\.env.prod -f deploy\prod\docker-compose.yml ps
docker logs -f quick-entry-prod-api-1
docker logs -f quick-entry-prod-ai-1
```

- 仅暴露 2001（Nginx）；
- 生产 AI 访问宿主机 MinerU：`host.docker.internal:8020`；
- 卷：`pgdata`（数据库）、`proddata`（data）；
- 账号：`admin` / `trial`（`deploy/prod/.env.prod`）。

### cpolar

- HTTP 隧道，本地 2001，地区 China VIP Top，固定二级域名；
- 外网访问会先弹 Basic Auth。

### 国内构建注意

- Docker Hub 被墙：`docker pull docker.m.daocloud.io/library/postgres:16` 后 `docker tag`；
- Maven 用阿里云镜像（Dockerfile 内置 settings.xml）；
- pip 用清华源；
- **Pillow 固定 10.4.0**，否则容器外无问题、容器内可能崩。

## 3. 数据备份 / 恢复

```bat
:: 备份
docker exec quick-entry-prod-db-1 pg_dump -U quickentry -d quickentry_prod -Fc -f /tmp/backup.dump
docker cp quick-entry-prod-db-1:/tmp/backup.dump .\backup-20261024.dump
:: 恢复
docker cp .\backup-20261024.dump quick-entry-prod-db-1:/tmp/backup.dump
docker exec quick-entry-prod-db-1 pg_restore -U quickentry -d quickentry_prod --clean --if-exists /tmp/backup.dump
```

文件数据在 `proddata` 卷，备份卷或同步到对象存储。

## 5. 排障手册

| 现象 | 处理 |
|---|---|
| AI 1003 端口在但超时 | 检查孤儿 python 进程；`multiprocessing` 子进程可能残留；无 reload 运行 |
| AI 启动崩溃 `_imaging` DLL 0x4551 | Pillow 回退 10.4.0 |
| pdfium 加载失败 | pypdfium2 固定 4.30.0；不要 force-reinstall |
| 1002 重启无效 | 监听在 127.0.0.1，netstat 用 `findstr :1002` 取 PID；杀掉再起 |
| 新 Controller 404 | 类上必须 `@RequestMapping("/api")` |
| MinerU `local_available:false` | 刚启动加载模型，等 40s；或 8020 未起 |
| 任务卡 running | 看 `data/tasks/{id}/state.json` 与 `logs/ai.err`；失败可 retry |
| 图片 404 | `storage_key` 是否含 `{{blank}}` 残留；`/assets` 已做 404 |
| 分栏明显错误 | 审核页用「按几何」重算；或改提示词后新任务 |
| Vite 启动报 Rollup 原生模块被拦 | Windows 安全中心放行，或删 node_modules 重装 |
| Docker 拉镜像失败 | 用 daocloud 镜像源 |
