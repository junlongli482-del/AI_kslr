# 04 · AI 流水线与提示词

AI 服务：`apps/ai/main.py`，端口 1003，无 `--reload`（避免 pdfium 崩溃留下孤儿 worker）。

## 1. 任务入口

```
POST /process   {task_id, files, mode, stage...}
GET  /tasks/{id}         → 状态、阶段、错误
POST /tasks/{id}/retry
POST /validate   {result}
POST /region-recognize
POST /question-rubric
GET  /prompts ...        → 提示词管理
```

Java 每 2.5 秒轮询 `/tasks/{id}`，同步到 `qe_task.status/stage`。

## 2. 处理阶段（顺序不能乱）

| # | 阶段 | 输入 | 输出 | 说明 |
|---|---|---|---|---|
| 1 | 识别 | PDF/图片 | markdown + blocks(bbox) | 本地 MinerU 优先，云端兜底 |
| 2 | 栏数判定 | 每页原图 | `{columns, confidence, reason}` | **独立调用，在结构化之前** |
| 3 | 结构化 | markdown + blocks | papers/questions/regions | 输出题框、题组、小问、sections/bands |
| 4 | 答案抽取 | 答案文档 | answers[] | 支持集中答案、随题答案 |
| 5 | 答案匹配 | 题目 + 候选答案 | 题目 answer/analysis | 语义匹配，跨页/跨节 |
| 6 | 填空匹配 | 题干 + 答案 | blanks[].answer | 学生用书场景 |
| 7 | 打标 | 题目 + 前缀 | 题型/子形态/知识点/难度 | 学科前缀，见第 4 节 |
| 8 | 题框/裁图 | 题目 + 页几何 | regions + 图片 | 图片按几何分组、跨页拆分 |

阶段失败会写 `state.json` 的 `error`，任务进入 `failed`，可从 UI 重试；已完成阶段的 LLM 缓存会复用。

## 3. 关键提示词与约束

### 结构化

- 输入：每页 markdown + 块 ID + 坐标；
- 输出示例是**真正的契约**：示例里没有的字段，模型就不会给。改字段必须同步改示例；
- 块 ID 必须写全（`d4a7b2c1-b12`），短 ID 会失败（后端有后缀容错但不要依赖）；
- 题组：一个 question + `subquestions[]`，小题要有稳定 `subquestion_id`；
- 学生用书：`sections` 只放「第X章/第X节」横幅，`bands` 放「重点探究」等板块横幅；范围 `[start, next section)`；排除上一节尾巴与下一节开头；
- 填空：必须保留 `{{blank}}`/`{{blank:n}}`，不得改写原文；
- 答案：不编造；没有就留空。

### 栏数判定

- 只发页图，发前几页 + 采样；
- 与几何判定冲突时记 `paper.column_conflict`，审核页出现「按 AI / 按几何」；
- 冲突默认显示 AI，允许人工选。

### 答案匹配

- 一次把题目与全部候选答案给模型，按语义匹配；
- 无匹配返回空，不要硬塞；
- 匹配失败会进审核 issue。

### 打标（重点）

- 21 个 `(学段,学科)` 前缀，文件：`apps/ai/tagging/prompts/prefix-{stage}-{subject}.txt`；
- **前缀必须按文件原文读**，不能模板拼接；任何字符变化都会让缓存失效；
- 前缀里已含：角色、题型+子形态、知识点树、判定顺序、难度公式、输出格式；
- user 消息只放题目（题干、选项、小问、答案、解析 + 题干/小问图片，最多 4 张）；
- 输出：

```json
{
  "question_type": {"code":"qt2701","name":"单选题","confidence":0.98},
  "sub_type": {"name":"4个选项","confidence":0.9},
  "knowledge_points": [{"id":"4700","name":"等差数列","role":"primary","confidence":0.9}],
  "difficulty": {"score_rate":0.42,"band":"中档","reason":"…"},
  "kp_note": "",
  "flags": []
}
```

- 校验：题型 code 在清单、子形态属于该题型、知识点 id 在树里、≤5 个、难度 0–1；
- 失败自动重试 1 次；仍失败 `tag_status=tag_failed`，审核页可手动重生成；
- 难度 0–1（1 最难），**不得用知识点个数推算**；
- 语文三科给 level≥2 全层节点，其余学科只给叶子（避免假精确）。

## 4. 提示词覆盖

- 默认值：`core.py` 常量（结构、栏数、答案、匹配、填空匹配、评分标准）；
- 打标默认值：`tagging/prompts/*.txt`；
- 覆盖值：`data/settings/prompts.json`，结构 `{key: {current:{content,revision,sha1,updated_at}, history:[...]}}`；
- 运行时 `prompts.get_prompt(key, default)`，按 mtime 缓存，保存后立即生效；
- 前端「提示词」弹窗可编辑、保存、恢复默认、回滚历史；
- 27 个 key：6 个固定 + 21 个 `tagging:{slug}`。

## 5. MinerU

- `MINERU_PROVIDER=auto|local|cloud`；auto 先本地后云端；
- 本地：`POST http://127.0.0.1:8020/v1/parse`（`mineru-kit api-server`），standard 档，并发 2；
- 云端：`MINERU_API_KEYS` 多 key 轮换，403/过期自动换；
- 本地不可用时等待/回退云端；健康检查超时很短，刚启动会误报 `local_available:false`；
- 页图与 `*_content_list.json` 存入任务目录，供结构化与裁图使用。

## 6. 模型与成本

- 默认渠道 DeepSeek（`deepseek-flash`），失败按策略切备用渠道；
- 每次调用记录 `usage`（prompt/completion/cached_tokens）到 `llm/*.json` 与成本接口；
- 打标前缀 3.8k–16.4k token，同科连续跑可命中缓存；缓存命中率看 `cached_tokens` 占比；
- 结构化/匹配是主要开销；重试会复用缓存，不会重复计费（同请求 hash）。

## 7. 已知坑

1. 提示词示例缺字段 → 模型不给该字段（历史事故：sections/bands 丢失）；
2. 短块 ID → 整题失败（已加容错，但提示词要写全 ID）；
3. 正则回填填空 → 已彻底删除，只信 AI 输出；
4. 页码/坐标混用 → 所有 bbox 必须 0–1，配 `page_index`；
5. 并发 >2 时 pdfium 偶发崩溃 → 已加 `PDFIUM_LOCK`，本地并发建议 2；
6. 修改前缀后缓存全失效，属预期，不要以为是 bug。

## 8. 2026-10-25 新增与变更

- **新增调用 `paper-attributes`**：结构化之后、`normalize_paper` 之前，每份试卷一次。
  输入只要卷名 + 文件名 + 已识别属性 + 首页图，输出试卷属性、卷面时长/满分/题量，带 confidence。
  只补空值，不覆盖结构化已识别的结果；失败只记 issue，不中断流水线。
  可用 `PAPER_ATTRIBUTES_ENABLED=0` 关闭。
- **卷型收敛为 26 值**（25 个组卷网原值 + 其他），旧值按别名归位；`exam_nature` 由卷型派生，不可手填。
- **打标输出增加 `grading_method`**（program / ai）：程序只能比对字母答案与判断勾叉，
  按“学生答出来的形态”判而不是按题型名判，题组含任一不能程序批的小题即整题 ai，不确定给 ai。
- **子形态只由结构决定**：小题 ≥2 才是 `group`，否则 `single`；模型自造的子形态名只留痕在 `question_type_sub_raw`。

## 9. 已知缺口

- 语文、英语的“一模/二模/联考”卷名写法尚未用真实卷名验证解析覆盖率。
- 前端下拉目前是 `enums.py` 的镜像，`/enums` 接口已提供，后续应改为直接拉取。
