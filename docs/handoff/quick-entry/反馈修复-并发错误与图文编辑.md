# 并发、错误详情与图文编辑修复

日期：2026-10-15。范围：用户本轮六张截图与公式渲染追问。

## 问题与根因

1. 任务长期显示排队：Java `TaskService.sync` 只同步 `running`。一旦同步到 Python 的 `queued`，下次轮询直接跳过；任务之后即使完成或失败，数据库与页面也不更新。此前 Python 还写死默认三个处理名额。
2. 处理失败缺少依据：LLM 适配层只记录异常类名和 HTTP 状态码，没有保留供应商错误消息、具体调用名称、失败阶段。
3. 公式显示源码：AI 使用合法的 LaTeX 分隔符 `\(...\)`、`\[...\]`，前端只解析 `$...$`、`$$...$$`。Markdown 随后把分隔反斜线作为转义符消耗，保存的旧编辑文档还会保留损坏的显示形式。不能把问题笼统归结为 AI 不会生成公式。
4. 图框存在但题干缺图：`block_ids` 中有图片块，AI 的 `stem` 却遗漏 Markdown 图片引用。切题区域与题干内容此前是两条独立链路，没有一致性补齐。
5. 补图要求填写资产地址：编辑器只插入已有 URL，没有图片上传、剪贴板或拖入接口。

## 并发与状态设计

- Python `TaskScheduler` 使用 Condition 管理运行集合和 FIFO 等待集合，任务 ID 去重。
- `max_concurrency=0` 表示不设置本地并发名额上限；正整数表示最多同时运行的任务数。没有固定的“三个任务”上限。
- 增大并发或切换到 0 时，立即唤醒等待线程；任务完成或失败均在 finally 释放名额；降低上限不取消现有在途任务。
- 设置落盘到 `data/settings/processing.json`，优先于启动环境变量。界面显示实际运行与等待数量。新环境默认 0，用户可以在页面改为正整数。
- 供应商返回 429 属于外部限流，仍会明确报告；无本地上限不等于外部服务无限额。
- 请求先保存到 `tasks/{id}/request.json` 再启动。服务启动检查 queued/running/pending：已有完整结果则恢复 ready；否则使用请求与成功阶段缓存续跑。不会自动重复执行 failed 或 ready 任务。
- Java 持续同步 queued/running/pending。ready 结果仍遵守原约束：不覆盖已经存在的人工审核稿。
- 此实现针对单个本地 AI 服务进程，不把线程调度描述成多实例分布式队列。

## 接口

| 接口 | 输入 | 输出 |
|---|---|---|
| GET `/api/quick-entry/settings/concurrency` | 无 | max_concurrency、unlimited、running、queued |
| PUT `/api/quick-entry/settings/concurrency` | `{ "max_concurrency": 0 }`，或正整数 | 保存后的设置及实际任务数量 |
| POST `/api/quick-entry/tasks/{id}/images` | multipart 字段 file | 本任务资产 URL、文件名、字节数、可读取的像素尺寸 |
| GET `/api/quick-entry/tasks/{id}` | 任务 ID | 原字段及可用的 error 对象 |

图片上传独立于源文件上传：处理完成之后仍能补图，不会改变已上传试卷和答案文件。

## 错误协议

失败状态保留 stage、service、operation、type、status_code、detail、hint、retryable；多渠道失败另外保留 attempts，每项记录渠道和模型。读取超时显示读取 300 秒／连接 25 秒的配置，HTTP 524、429、401、403分别给出相应处理提示。模型输出达到上限导致 JSON 截断时明确显示 finish_reason=length。

供应商响应只摘取错误消息，必要时提取简短文本；密钥、Bearer 内容和 URL 查询参数在持久化前隐藏。旧失败记录只能展示此前实际保留的消息与调用日志，不伪造已经丢失的供应商响应。

## 数学渲染与编辑数据

- 渲染器支持 `$...$`、`$$...$$`、`\(...\)`、`\[...\]`，先提取数学片段再执行 Markdown，防止分隔符消失。
- 编辑器将数学片段转换成 mathInline 节点，保存 LaTeX 与 display 属性；序列化时统一输出美元分隔符。KaTeX 使用 trust=false。
- 旧编辑文档中带 LaTeX 命令的括号形式以及被拆成 `[ / 公式 / ]` 三段的显示公式，会转回数学节点；不对无法判断的普通括号文字猜测数学含义。
- AI 补缺提示词统一要求美元分隔符和正确 JSON 转义，但前端不依赖模型只输出一种形式。
- 未改变 MathLive／模板／源码选项，不宣称本次接入了商业 MathType。LaTeX 语法本身错误与答案内容正确性仍由现有人工审核承担。

## 图片一致性与人工补充

- AI 编排输入增加紧凑图片信息：完整 URL、原页坐标、页码、像素宽高；缓存兼容已完成的旧版结构化阶段，避免仅新增图片元信息就重复调用已成功阶段。
- 对每题依据已有 block_ids 检查原文图片引用。题干、选项、小问、答案和解析都没有引用时，将图片补入题干并记录待核对提示。不会把整张原页当题干插图。
- 旧草稿打开审核时执行同样的引用修复；保留人工编辑文档，只补缺图和迁移公式，不用重新生成的题干替换人工内容。
- 编辑器和只读预览都使用 image_layout。相对宽度依据原图 bbox 与本题区域计算，已有图片宽度元信息能够保留进编辑文档。
- 用户主动删除的图片记入 excluded_image_urls，重新打开时不强行补回；撤销删除或再次插入会解除排除。
- 题干、选项、小问、答案、解析编辑器均支持直接 Ctrl+V 图片、拖入图片和选择本地图片。上传后保存 URL，不把 base64 图片塞进审核 JSON。
- 上传过程中跟踪编辑选区随事务的映射，避免等待上传时继续输入导致插图落错位置；切到另一题或销毁编辑器后，不把迟到图片插进新题。
- 原卷区域增加“插入题干”，允许用户直接利用已有裁切补充内容。
- 答案文件采用与题目文件一致的拖拽选择区，仍支持独立答案、多文件和其他试卷答案混入；不额外调用识别接口。

## 生效方式

前端通过 Vite 热更新。Python 开发进程会在代码写入后自动重载，未完成请求按上述规则恢复；已落盘阶段会复用，尚未落盘的外部调用可能需要重做。Java 需要在原窗口 Ctrl+C 后运行 `scripts\dev.cmd api`，不需要打包 jar。详细结果以本轮执行日志为准。
