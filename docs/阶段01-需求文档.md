# 智慧教学平台｜阶段01需求文档

版本：v1.1｜日期：2026-10-14｜状态：已确认，阶段01正式开发交接版（单一全栈开发AI）

确认记录：用户已确认本阶段范围、架构基线，以及后台更换绑定运营人员、教师姓名与手机号两项必填。本文与开发文档为阶段01开工依据；后续需求变更须记录版本与影响范围。

## 0. 工程师必须了解的完整产品方向

这是一套面向学校与教师、围绕纸质教辅和纸笔作业建设的智慧教学平台。阶段01只是整个产品的账号与学校基础，不能将其理解为最终只做几个学校管理页面的独立小系统。

完整业务方向：纸质教辅/自编卷 → 教师布置 → 学生纸笔作答 → 扫描/拍照上传 → 身份与卷面核对 → AI批阅 → 教师复核 → 讲评与学情 → 错题重练/分层练习 → 再次作答与效果比较。

| 长期能力域 | 需要为它保留的基础边界 | 阶段01是否实现业务 |
|---|---|---|
| 账号与权限 | 登录账号、平台运营资格、校内信息分别存储 | 是，按本阶段范围 |
| 学校组织 | 学校、人员关联；以后增加年级、班级、学生、任职 | 仅学校与教师关联 |
| 教辅与题库 | 教辅批次、章节、知识点；题目身份与版本独立 | 否 |
| 作业与收件 | 布置状态、扫描批次、页面与文件元数据独立 | 否 |
| 批阅与复核 | AI执行与业务结果分开；教师改分留痕 | 否 |
| 学情与重练 | 基于已产生结果分析，不侵入账号模块 | 否 |
| 消息与算力 | 通知发送与业务规则分开；计量可追踪 | 否 |
| 移动端与独立考试 | 通过服务接口使用基础能力，不复制账号与学校规则 | 否 |

以上是产品方向与模块预留，不等于一次性批准所有后续功能。下一阶段需求仍独立确认，不能把总产品目标全算作阶段01验收内容。

网页教师端与运营后台是第一阶段入口；后续可扩展微信小程序与独立考试部署单元。Java业务服务负责业务与权限，未来Python服务负责识别/批阅执行，二者通过接口通信。

旧资料将规模估计为6,000—10,000所学校、约200名教师/校，并提出约2万同时在线教师及扫描峰值目标。这些是长期架构输入与待验证的容量假设，不是现有系统能力，也不要求第一阶段实现扫描压测。架构必须允许业务API多实例部署、数据库索引优化、AI计算独立扩容及未来异步任务接入。

### 基础建设同样属于阶段01交付

业务闭环完成之外，还必须完成技术栈固定、按业务分模块的代码结构、统一认证与学校授权、迁移、外部服务适配、接口契约、关键测试、自动模块边界检查、环境配置与交接记录。具体工程约束见开发文档第2节，不能以“第一阶段功能少”为理由省略。

功能范围由本需求文档定义；实现架构、目录和质量门槛由开发文档定义。工程师应读取这两份文档全文，本交接不要求依赖其他历史材料才能理解核心规则。

## 1. 阶段目标

完成网页运营端和网页教师端的学校、账号与人员管理闭环：

1. 运营登录后台，创建学校并绑定负责该校的运营人员。
2. 运营在后台管理学校、账号和人员关联。
3. 被绑定的运营人员登录教师端，进入绑定学校，手工添加或批量导入教师。
4. 教师通过模拟短信验证完成首次激活，设置密码，登录后看到学校与身份。
5. 同一账号关联多校时，可以切换学校，各校数据保持隔离。

本阶段的短信验证仅用于开发、联调和受控验收。真实对外使用前必须接入可靠的身份验证方式，不能将页面展示验证码作为真实手机号验证。

## 2. 已确认的范围

| 项目 | 已确认要求 |
|---|---|
| 客户端 | 网页运营端、网页教师端 |
| 账号 | 手机号全局唯一；同一账号可以关联多所学校 |
| 教师显示姓名 | 按学校分别保存；修改本校显示姓名不影响其他学校 |
| 运营后台范围 | 运营人员可管理全部学校 |
| 教师端运营范围 | 运营人员只能管理自己绑定的学校，可绑定多校 |
| 校内身份 | 第一阶段只做教师；绑定运营人员通过单独的管理资格管理人员 |
| 人员录入 | 手工添加、Excel批量导入；整批校验通过才能导入 |
| 日常登录 | 手机号＋密码、手机号＋验证码，两种方式均支持 |
| 解除学校关联 | 仅运营后台提供；教师端不提供按钮，也不得调用成功 |
| 短信 | 暂用模拟短信验证码，预留阿里云短信接入 |
| 基本维护 | 修改学校信息、修改教师本校姓名、在教师端停用/恢复本校使用权、在后台解除学校关联 |
| 运营账号来源 | 部署时初始化第一个账号，后续可在后台新增运营人员 |
| 学校重复提示 | 同名同地区时提示重复风险，运营明确确认后仍可创建 |
| 手机号纠错 | 不直接修改手机号；后台解除错误学校关联，再添加正确手机号 |
| 运营换绑 | 后台编辑学校时可更换负责运营人员；一校保持一名，旧人员管理资格立即失效，新人员立即获得 |
| 教师录入字段 | 手工与Excel均为本校显示姓名、手机号，两项必填 |

普通教师没有运营后台权限，也没有教师端人员管理权限。学校管理资格与“教师”身份分开判断；运营人员进入教师端不等于授予所有教师管理权限。

### 角色与操作对象

| 角色/使用场景 | 操作对象 | 本阶段明确的权限 |
|---|---|---|
| 平台运营，使用运营后台 | 全部学校及相应教师校内信息 | 新增运营人员、建校、绑定运营人员、人员管理、解除学校关联 |
| 学校管理员，使用教师端 | 自己绑定学校中的教师校内信息 | 查看、手工添加、导入、修改本校显示姓名、停用/恢复本校使用权；不修改其他学校 |
| 普通教师，使用教师端 | 自己关联学校中的本人信息 | 登录、查看本人校内信息、切换学校；没有管理其他教师的权限 |

第一阶段学校管理员的资格来自后台的运营人员与学校绑定，不额外设计其他校内角色的分配体系。“修改教师姓名”指学校管理员修改指定教师在本校的显示姓名，不是修改管理员自己的姓名，也不是全局改名。

## 3. 学校与人员信息

### 学校

| 信息 | 要求 |
|---|---|
| 学校名称 | 必填 |
| 省、市、区/县 | 必填；特殊行政区划的处理由前后端统一约定 |
| 学段 | 必填，多选：小学、初中、高中、职高 |
| 详细地址 | 选填 |
| 备注 | 选填 |
| 绑定运营人员 | 创建学校时必选一名已有运营人员 |

不设置联系人、联系电话字段。学校名称及省市区相同，提示已有同名同地区学校并展示候选学校及详细地址；运营可以取消，也可以明确选择“仍然创建”。确认后新建独立学校记录。不能设置“名称＋省市区”硬性唯一约束；重复点击同一次提交不得创建多条记录。

### 人员

教师录入信息仅为本校显示姓名、手机号，两项必填；手机号格式限制由工程在模板与接口契约中统一注明，更正流程按下文执行。手机号用于识别和匹配同一账号，登录凭证属于账号；显示姓名存于学校关联。同一手机号在不同学校可有不同显示姓名，不生成另一套账号或密码。显示姓名不作为账号唯一性或真实身份一致性的判定依据。

业务唯一性分为两层：手机号识别登录账号；“手机号＋学校”唯一识别教师在该校的信息。例如同一手机号在A校叫“李四”、在B校叫“张三”，两条校内信息独立维护，登录后可切换查看。

手机号不提供直接编辑入口。发现某校教师手机号录错时，由后台解除该错误账号与本校的关联，再在本校添加正确手机号及显示姓名；错误账号原有的其他学校关联不变，不执行全局改号、账号合并或姓名转移。

### 运营账号

部署时初始化第一个运营账号，不能通过开放注册获取运营资格。后续运营在后台按手机号新增运营人员；手机号已有账号时复用该账号并增加运营资格，不创建第二个账号，不修改该账号在各校的教师姓名。

运营人员的管理显示名与教师的本校显示姓名是不同字段，不自动同步。新增运营人员填写运营显示名、手机号；运营显示名仅用于后台选择与识别负责人员，不作为教师的各校姓名。

## 4. 功能与业务规则

| 编号 | 功能 | 预期行为 |
|---|---|---|
| R01 | 运营登录 | 具有运营资格的账号可进入后台；普通教师访问被拒绝 |
| R02 | 学校列表 | 查看学校名称、区域、学段、绑定运营人员；支持进入学校详情 |
| R03 | 创建学校 | 校验必填信息及运营人员资格；同名同地区先提示，可确认后继续；学校与运营绑定成功后才算创建完成 |
| R04 | 修改学校与运营换绑 | 后台修改学校基本信息、选择有效运营人员替换原绑定；一校保持一名，旧人员管理资格立即失效，新人员立即获得 |
| R05 | 手工添加教师 | 在明确的学校中添加人员并建立关联；重复手机号复用账号，不生成第二个账号 |
| R06 | 教师端人员管理 | 绑定运营人员可查看并管理该校教师；普通教师不能访问此功能 |
| R07 | Excel导入 | 下载模板、上传文件、检查内容、展示详细错误；存在错误时整批不导入，全部校验通过才能提交 |
| R08 | 首次激活 | 已录入的教师通过模拟验证码验证，设置密码；不提供面向陌生用户的开放注册 |
| R09 | 登录与退出 | 支持手机号＋密码、手机号＋验证码；教师登录后看到学校、姓名、身份；退出后当前会话失效 |
| R10 | 多校切换 | 只展示本人有资格进入的学校；切换后页面数据与权限同步更新 |
| R11 | 未关联学校 | 已存在且可用的账号进入教师端后显示“你的账号还没被分配到学校，请联系运营人员” |
| R12 | 忘记密码 | 已存在账号通过模拟验证码验证后重置密码，不生成新账号 |
| R13 | 修改教师本校显示姓名 | 本校管理人员在教师端修改指定教师的本校显示姓名；仅更新该教师与本校的关联，不修改其他学校，不改变账号身份及登录凭证 |
| R14 | 停用/恢复教师本校使用权 | 学校管理员在教师端操作；停用后该教师不能进入或访问本校数据，账号仍可登录并使用其他有效学校；恢复后重新获得本校使用权，姓名及关联信息保留 |
| R15 | 解除学校关联 | 仅在运营后台操作；失去该校访问资格，其他学校关联保留；账号本身保留 |
| R16 | 新增运营人员 | 后台添加运营资格；手机号存在则复用账号，不改各校教师姓名；新账号通过激活流程设置密码 |
| R17 | 手机号纠错 | 后台解除错误学校关联，再添加正确手机号；没有直接编辑手机号或合并账号入口 |

学校管理员在教师端完成本校教师添加、导入、改名、停用与恢复，不通过跳转后台代替本端流程。普通教师自行改名尚未纳入已确认功能。停用保留“手机号＋学校”记录，恢复直接更新本校使用权状态，不重新创建账号、不改变密码、不更改其他学校。

本阶段不将教师校内停用实现为全局账号封禁。解除关联仍仅在后台提供，与教师端的可恢复停用是不同操作。教师所有学校均停用时仍可登录，显示“暂无可使用的学校，请联系学校管理员”；不将校内停用显示为密码错误。

### Excel错误反馈（已确认）

- 每条错误必须包含原文件行号、字段/列名、错误原因和修改方法；适合展示时提供错误单元格的原值。
- 示例：第8行，手机号列，值“1380013800”：手机号位数不符合模板要求；请补全并核对手机号。
- 同行有多个错误时逐项展示；文件内重复手机号应指出涉及的行号。
- 文件级错误应说明文件格式、缺少的工作表/列等实际原因，不能只返回“导入失败”。
- 检查结果尽量一次展示全部可定位错误，避免每次只反馈一条、反复上传。
- 存在错误时不创建账号、不新增学校关联；修改文件后重新检查，全部通过才能导入。
- 账号已存在于其他学校且显示姓名不同，不构成身份冲突；复用手机号对应账号，新关联采用本次录入的本校显示姓名，不修改其他学校。
- 同一“手机号＋学校”的导入信息与已有信息完全一致时跳过；信息不一致时报错，不自动覆盖、不自动合并，任一此类错误均阻止整批导入。
- 模板固定为姓名、手机号，两项必填；比较的是本校导入字段，学校由操作上下文确定。以后增加导入字段时必须明确比较字段范围并更新需求与契约。
- 文件内同一手机号出现多次，信息完全一致时保留一个待导入项并标记其余为跳过；信息不一致时列出冲突行并阻止整批导入。
- 冲突示例：第8行，本校显示姓名列，本次“张三”、本校已有“李四”；提示同一手机号在本校的信息不一致，请核对名单。确需改名时由管理人员在本校教师编辑入口修改，再上传正确名单。
- 不得依据其他学校姓名来判错或在错误详情中泄露其他学校人员信息。跳过是正常检查结果，不是错误；全文件均为一致重复时返回“无需新增，全部跳过”。
- 已停用的校内教师再次导入，姓名与手机号一致时仍跳过，不自动恢复使用权；恢复必须由学校管理员执行独立操作。

### 模拟短信的边界

- 使用“发送验证码—输入验证码—验证”的交互，替换真实短信发送环节。
- 仅开发/测试环境显示模拟验证码，页面标明“测试验证码，未发送真实短信”。
- 模拟模式也应生成随机验证码，并处理有效期、使用一次后失效、发送间隔及错误次数限制。
- 不允许仅靠浏览器判断验证码是否正确，不使用对所有账号都有效的万能验证码。
- 正式环境禁止开启展示验证码的模拟模式。
- 阿里云资质就绪后替换发送服务，保留已确认的页面和业务流程。

日常登录同时支持密码和验证码；验证码的测试环境边界与激活、重置一致。

## 6. 暂不纳入

班级、年级、学生名册、任职与学科权限、完整校内角色、作业、扫描、AI批阅、学情、小程序、家长端、真实短信接入。

本阶段学校管理员由绑定运营人员承担；后续可再扩展校内人员担任管理员的授权流程。

## 7. 阶段验收

1. 运营账号能登录后台，普通教师不能进入后台。
2. 学校可保存多个学段，页面没有联系人、联系电话字段。
3. 新建学校必须绑定运营人员；成功后列表可见。
4. 绑定运营人员可从教师端进入绑定学校管理教师，不能管理未绑定学校。
5. 后台运营可管理全部学校，不受教师端当前学校限制。
6. 手工添加及Excel导入都能建立账号与学校关联；Excel有一行错误时整批无写入，检查结果逐项展示行号、字段、原因和修改方法。
7. 同手机号手工/导入重复出现，账号记录仍只有一条；同校关联不得重复生成。
8. 教师通过模拟验证码激活、设置密码；密码登录与验证码登录都能进入并看到学校与身份。
9. 同一教师可关联两校；切换后不残留旧学校数据。
10. 普通教师直接调用人员管理接口被拒；访问未关联学校的数据被拒。
11. 未关联学校的账号显示明确引导；验证码错误、过期、已使用显示可理解的反馈。
12. 学校管理员在教师端停用A校教师后，该账号仍可登录，已有会话也不能继续访问A校，但B校仍可使用；恢复后A校原姓名与关联保留。仅后台可解除学校关联。
13. 模拟验证码只在开发/测试环境出现，正式环境不能启用该方式。
14. 后端接口契约与实现一致，前后端完成真实联调，并记录验收结果。
15. 同一手机号在A校显示“张老师”、B校显示“张某”；将A校改为“张三”后，B校仍显示“张某”，账号记录仍只有一条。
16. 本校已有“手机号X＋姓名李四”，导入相同信息时跳过；导入“手机号X＋姓名张三”时报错，显示行号、差异字段、本次值、本校已有值及修改建议，整批无写入。
17. 新学校导入手机号X、姓名张三，即使该账号在其他学校叫李四，也正常创建新校关联，其他学校信息不变。
18. 文件内完全一致重复行跳过多余项，差异重复行报错并指明相关行号；全为一致重复的文件显示全部跳过，不创建数据。
19. 部署初始化第一个运营账号；后台可新增运营人员，已有手机号账号只增加资格，不生成第二个账号。
20. 同名同地区创建学校时先提示；取消则不创建，明确确认后可创建第二所独立学校；同一次提交重复点击不重复建校。
21. 手机号没有编辑入口；在后台解除错误校内关联后可添加正确手机号，其他学校关联与姓名不变。
22. 全部学校均停用时账号仍可登录，显示暂无可使用学校的引导；重复导入停用教师不得自动恢复，普通教师及其他学校管理员不能越权恢复。
23. 后端按业务模块组织文件，账号模块不依赖学校模块；学校模块只能使用账号模块公开接口，不访问其Mapper、Entity或数据库表。
24. 构建包含可运行的模块边界检查，循环依赖、跨模块访问内部类、Controller访问Mapper会使检查失败。
25. 数据结构变更仅通过迁移；应用运行账号无DDL权限；首次初始化与迁移可从空库重现。
26. 前后端技术版本锁定、OpenAPI与实现一致，提供模块卡片、部署说明、真实验证输出；不能只交付能演示的页面。
27. 后台更换绑定运营人员后，旧人员不能再管理该校，新人员立即可管理；旧人员若另有该校正常教师关联，普通教师使用权仍保留。
28. 手工添加与Excel导入缺姓名或手机号均被明确拒绝，导入指出原文件行号、缺失字段及填写方法。
